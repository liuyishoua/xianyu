# 发布准备与不确定结果

总部 `product.read` 仍表示账号隔离的工作台缓存读取，但现在同时提供 `publication_context`：本账号草稿、素材 ID/尺寸/访问路径、已保存地点、发布前字段与缺项。文件系统路径、凭据和其他账号素材不会返回。限制具体资源的授权仅返回获准草稿及它们的素材。草稿允许先保存缺少金额/图片/地点的内容，能力参数对此明确说明。

工作台保留原 PNG 文件，上传副本使用 JPEG 编码降低请求体大小，不改图片内容或账号选择。`无需邮寄` 的服务允许省略地点，并向平台传空地址；其余配送仍必须选择真实已保存地点。省略地址的最终平台接受性只能由实际发布回执证明，预检通过不等于发布成功。

发布记录保存 `publish_stage` 与 `publish_request_started`。图片/类目准备失败时，最终商品发布接口尚未调用，返回明确失败；只有进入最终请求之后发生的未知异常保留 unknown/uncertain。最终开始标记在发送前持久化，崩溃也不能误判为可重试。成功仍需要商品编号，并通过账号商品详情回读验证。未知业务回执的 `platform_action_performed` 为 null，不能声称已执行或未执行。

旧工作台只保存笼统 unknown，缺失原堆栈与阶段记录。受控重现和空商品列表是辅助信息，不能冒充旧请求的确定结果。原请求、草稿及原行动状态必须保留，不回填假 failed，不自动重发。

## 受控第二次提交

1. 先记录用户针对该未知发布明确允许第二次提交的决定；通用发布授权不替代未知结果重试决定。
2. 在原目标下保留旧 unknown 行动和工作台请求，创建独立的新行动/新草稿，并在记录中关联旧行动与具体用户决定。新行动固定一个新 request_id，参数保存后不可更换。
3. 复核真实账号、当前授权版本、发布授权及有效期。独立受控执行期间停止总部的并发规划，不更改其他账号授权或监听开关；未知旧行动不自动恢复调度。
4. 复用已审阅的正文、20元实际服务费和服务说明图；商品货款、实际运费另算，不虚构城市、会员资格、库存或配送能力。账号未保存地点时只能提交无需邮寄的服务，不冒充实际地点。
5. 只提交一次最终发布；失败保留阶段证据，未知则再次停止。成功必须回读商品详情的卖家归属、价格、正文及当前账号列表中的商品编号。模型文本不能证明完成。
6. 保留两次完整历史。原目标的业务完成依旧按总部的人类确认与证据规则处理。

真实素材与诊断记录位于工作台忽略的私有 `sam-service` 产物目录。测试使用 DemoPlatform；旧请求保持 unknown。用户明确允许后执行了单次第二提交，平台返回认证校验拒绝，新请求 failed；官方账号接口确认支付宝认证通过，但真人和闲鱼认证未通过，商品列表仍为空。两次请求与历史均保留，总部已记录具体认证阻塞并停止自动提交。

后续用户确认认证完成，官方账号接口三项认证均为 true；用户授权恢复后执行一次新的固定请求，但最终接口仍返回同一认证校验拒绝。发布预检 `limited=false`，账号 `hasViolation=false`，商品列表仍为空。普通认证标志不是最终发布接受的证明，当前不得继续使用“用户未做普通实名认证”解释阻塞。

官方网页发布脚本对该错误展示手机扫码认证，目标是公开 `identity_auth` 入口；网页通常在最终发布被拒绝后才展示二维码。私有产物目录保留可直接打开的无凭据公开认证链接和二维码，不通过再次点击发布来触发。用户若只看到已完成，应反馈实际页面提示，不能保证重复普通认证能解决。未来最终平台响应保存于账号私有 `publication-receipts`，不将认证票据或完整响应返回浏览器。

用户完成官方入口扫码后，一次授权发布已通过认证检查，转为明确的行政区校验拒绝；无需邮寄仍不意味着最终接口可以省略商品所在地。用户随后明确授权自行选择发布地区，采用官方发布页无定位时提供的北京东城区作为服务展示区域，并在正文说明其不是实际住址、现货或配送承诺。保留所有旧失败与未知记录。官方 `itemAddrDTO.gps` 格式为纬度、经度，SDK 原来的反向顺序已更正并以合成请求验证；不使用示例南京坐标冒充账号位置。

地区参数修复后的一次授权提交返回真实商品编号；官方详情显示福来day、20元、在线，账号列表出现同一商品且无其他商品，正文与授权草稿完全一致。私有 `publication-verified.json` 和同目标总部收据保存核验结果，原未知发布历史仍保留。实际发布已完成；总部业务结项依其本人确认约定保留待确认状态，不把自动核验伪造成用户确认。
